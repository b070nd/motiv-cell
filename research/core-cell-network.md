# Core cell network: research notes (air-gapped, deterministic, Go)

Date: 2026-11-09. Local toolchain: go1.27.1 darwin/arm64. Status tags: **VERIFIED** = read in the primary source (or reproduced by a local experiment on go1.27.1, stated as such); **UNVERIFIED** = secondary source, bibliographic record only, or not read. Local experiments were run in the scratchpad, nothing under `app/` or `data/` was touched.

## Summary

- **Floats are the biggest determinism hazard.** The same Go source gives different bits on arm64 and amd64 because the spec lets the compiler fuse `x*y+z`. Reproduced locally: `x*y+z` gave `8.67e-19` on arm64 and `0` on amd64 (GOAMD64=v1); `float64(x*y)+z` gave `0` on both. `math` docs disclaim bit-identical results across architectures. Integer or fixed-point in the cell rule (PROTOCOL Q-08 default) is the only fully safe choice. (A3)
- **Unicode and JSON output depend on the toolchain version.** `unicode` and `x/text/unicode/norm` tables are Unicode 15.0.0 for Go 1.21 to 1.26 and 17.0.0 for Go 1.27; `encoding/json` in 1.27 runs on the v2 implementation and emits different bytes for invalid UTF-8 unless `GOEXPERIMENT=nojsonv2`. Pin the exact toolchain, record `unicode.Version` in every output, regenerate goldens on upgrade. (A5, A8)
- **Air-gap works with stock Go.** Vendored build with empty module cache, `GOPROXY=off GOFLAGS=-mod=vendor GOTOOLCHAIN=local -trimpath` succeeded and gave identical binary hashes from two directories; `-mod=mod` failed with "module lookup disabled". `go.sum` is not consulted in vendor mode, so vendor integrity needs your own manifest. (A7, B1)
- **A stdlib-only guard is feasible** (go/parser + go/ast prototype caught forbidden imports, `init()`, package-level vars, `time.Now`) but is syntactic; type-aware checks need `golang.org/x/tools`. Transitive import checks need `go list -deps`: `text/template` pulls `net/url` and `net/netip`. (B3)
- **Cell formalism:** the standard model for heterogeneous stateful nodes is Kauffman's Boolean network (per-node function of its inputs) and graph CA; synchronous double-buffered update is deterministic, random-order asynchronous update is not, fixed-order asynchronous update (sequential dynamical systems, deterministic ARBN variants) is. (C)
- **Lehnert plot units already contain a motivation link** (affect states +, -, M joined by m, a, t, e links). The only automated version found (AESOP) needs a parser, pronoun resolution and polarity lexicons and reached F about 44%. Most narrative formalisms need parsing plus coreference; only Reagan-style arcs (lexicon + sliding window + SVD) need neither. (D)
- **Finance lexicons are licence-bound:** Loughran-McDonald is free for academic research, commercial use needs a licence; Financial PhraseBank is CC BY-NC-SA 3.0; ProsusAI FinBERT weights are CC BY-NC-SA 4.0 per its model card; NRC Emotion Lexicon forbids redistribution. No permissively licensed stock-news corpus was found; SEC EDGAR is free to reuse but is filings, not news. (E)
- **Literature corpora are easier:** ELTeC v1.1.0 has 14 languages (including Hungarian), 1840 to 1920, TEI XML, texts public domain, markup CC BY; LitBank (CC BY 4.0) adds entity, event, coreference and quotation labels for 100 English works. Essays and news reports are not covered by either. (F)
- **Krippendorff alpha** nominal and interval are fully specified (worked example: nominal 0.743); unitizing alpha has worked numbers (0.488, 0.515, 0.616) in Krippendorff's own text. No standalone Go package exists; reference unitizing software is Java; Mathet's gamma needs random resampling, so it needs an injected seed. (G)
- **Go NLP:** `jdkato/prose/v3` is active (v3.2.3, 2026-10-31, MIT) but has `init()`, package-level lazy globals and embedded CC BY-SA models, so it violates the project's own no-globals rule if held to it; `rivo/uniseg` implements UAX #29 at Unicode 15.0.0 and splits "Mr. Smith" after "Mr."; no Hungarian POS/NER model exists in prose. (H)
- **Go 1.27 adds generic methods** on concrete types, but interface methods still cannot have type parameters; a heterogeneous cell network therefore needs a non-generic interface at the seam. (I)

Answer to "is `(state, neighbour inputs) -> state` the standard formalisation?": yes for CA, Boolean networks and graph CA (verified for RBNs; CA/graph-CA definitions not read). The standard caveat is the schedule: determinism holds for synchronous double-buffered update and for any fixed total update order, not for random-order asynchrony.

OPINION: use a synchronous tick with double buffering (all cells read tick t, write tick t+1), neighbour inputs presented in a canonical sorted order (by cell ID), and treat any "event-time" ordering (Q-03 B/C) as a deterministic priority queue keyed by (time, cell ID). Heterogeneous rules per cell are normal in Boolean networks, so per-cell rule values fit the formalism.

## I. Generic-core design in Go

| # | Topic | Finding | Source | Status |

| I1 | Generic methods | Go 1.27 spec: a method declaration may specify type parameters (a "generic method"), which must be instantiated before use. OPINION (design sketch, not from sources):
- Keep the engine domain-agnostic by making the unit of generality the transition: `type Transition[S, In any] func(state S, inputs []In) S`, a pure function (plain `func` or struct method with no hidden state), plus `type Cell[S, In any] struct{ id ID; state S; step Transition[S, In] }`.
- At the lattice level, hide `S` behind a small non-generic interface (for example `Step(tick) Output`) or fix the message type to one `Signal` value type in `model`, so heterogeneous cells fit in one slice.
- Domains (finance news, literature) are plug-ins that supply lexicons, gazetteers, `Transition` values and a taxonomy via explicit constructors (`NewX(cfg, deps)`); wire only in `cmd/`.
- Options: use plain config structs validated in the constructor; use functional options only where optional dependencies are many (clock, rng). Inject `rng.Source` and `clock.Clock` as interfaces or small value types, never package variables.

## Open questions for the user

Ordered by how much they block the design.

1. **Numeric policy in the cell rule (blocks `cell`, `engine`, golden tests).** Research settled that float results differ across arm64/amd64.
   - A. Integers / fixed-point only in the rule, floats in reports only. Trade-off: bit-exact everywhere; need scaling conventions and no log/exp.
   - B. float64 with explicit `float64(...)` rounding on every product, no transcendental functions, CI on both architectures. Trade-off: natural formulas; relies on discipline and on the compiler rule in the spec.
   - C. float64 freely, goldens per architecture. Trade-off: simplest code; two golden sets and no cross-machine byte identity.

2. **Licence posture of the finished program (blocks lexicon and corpus choice).** LM, PhraseBank, FinBERT weights, NRC and FNSPID are non-commercial or restricted.
   - A. Private research use only: use LM, PhraseBank, and the NRC lexicon locally (never redistributed). Trade-off: best resources; cannot ship or sell.
   - B. Keep commercial/open release possible: build lexicons from scratch and from PD/CC BY sources (EDGAR, ELTeC, LitBank). Trade-off: safe; large labelling effort and weaker accuracy.
   - C. Plug-in lexicons with a licence manifest, core free of restricted data. Trade-off: flexible; more interface work and per-user licence burden.

3. **What data enters for the stock-news target (Q-04).** No permissively licensed wire-news corpus was found.
   - A. User-supplied licensed feed in JSONL. Trade-off: realistic news; you carry the licence and the volume.
   - B. SEC EDGAR 8-K and exhibit text via the Feed/Oldloads archives (public, 10 req/s, SGML/HTML parsing to write). Trade-off: free and legal to reuse; it is disclosure prose, not journalism.
   - C. Small hand-written/hand-labelled fixtures only (PROTOCOL Q-15 default). Trade-off: fully deterministic and shareable; too small to test the network at scale.

4. **How actors and events are found (Q-05, blocks `actors`, `voids`, `evidence`).** Literature needs more NLP than news.
   - A. Gazetteer plus name-variant rules plus lexicons, no parser. Trade-off: fits air-gap and determinism; low recall on pronouns and literary text.
   - B. Vendored `prose/v3` for tokens/POS/sentences. Trade-off: usable now; has `init()`/globals, CC BY-SA models, English only (no Hungarian).
   - C. External offline preprocessor (BookNLP/spaCy-class) writes annotation files the core reads. Trade-off: best linguistics; heavy Python/neural toolchain outside the Go core.

5. **Cell semantics (Q-02, Q-07).** Which published structure should the Motivation Cell follow?
   - A. Own cell (owner, void, evidence, peak) with same-void edges, no derived numbers. Trade-off: exactly your spec; no external validation of the semantics.
   - B. Plot-unit-compatible: states +, -, M with m/a/t/e links between cells. Trade-off: published, annotated lineage (Lehnert, AESOP); more link types to implement and judge.
   - C. Actantial (Greimas) roles on top of A. Trade-off: richer roles; the only sources found were not readable here and need rule definitions.

6. **Update schedule and tick axis (Q-03).**
   - A. Synchronous double-buffered tick per sentence/discourse position. Trade-off: simplest determinism proof; no story-time reasoning.
   - B. Event-driven priority queue keyed by (timestamp, cell ID). Trade-off: right for news; needs a total tie-break order and clear time source.
   - C. Separate fabula time with Allen/TimeML relations. Trade-off: handles flashbacks in literature; temporal extraction is the hardest NLP part and largely ML-based.

7. **Void taxonomy (Q-06).**
   - A. Open text plus normalised label. Trade-off: no early commitment; same-void matching is harder to make deterministic.
   - B. Closed set seeded from Maslow/Reiss (Rashkin et al. 2018) with a finance extension. Trade-off: published labels, easy matching; may not fit finance goals.
   - C. Closed finance-only list first (capital, approvals, litigation, liquidity) and revisit for literature. Trade-off: fast for news; rework for novels.

8. **Evaluation depth (G).**
   - A. Nominal and interval alpha on predefined units plus exact span F1. Trade-off: closed-form, fixtures in hand; ignores boundary disagreement.
   - B. Add Krippendorff unitizing coefficients (U_D, u_D) from section 12.4. Trade-off: boundary-aware and closed-form; only worked numbers in the text, no overlapping spans, no Go reference.
   - C. Add Mathet gamma. Trade-off: handles overlaps and categories; needs an LP solver and a seeded resampling RNG.

9. **Third-party dependency policy (Q-17).**
   - A. Stdlib only. Trade-off: strongest guard; write own sentence splitter and stemmer.
   - B. Stdlib plus a short vetted vendored list (e.g., `x/text`, `uniseg`, `snowball`). Trade-off: saves work; need a vendor hash manifest and a rule that the guard exempts vendor.
   - C. Allow larger NLP libraries (prose). Trade-off: more capability; globals/init and model licences enter the build.

10. **Randomness (Q-08).**
   - A. `math/rand/v2` PCG with explicit seed. Trade-off: no code; no found contractual stability for raw PCG streams across Go releases (the `Rand` methods are locked).
   - B. Own PCG/SplitMix64 with committed test vectors. Trade-off: guaranteed frozen stream; about 30 lines to maintain.
   - C. No RNG in the core at all (only gamma would need one). Trade-off: simplest; rules out sampling-based evaluation.

11. **Canonical output format.**
   - A. `encoding/json` with a pinned toolchain and no floats in output. Trade-off: least code; byte output depends on toolchain/GOEXPERIMENT for edge cases.
   - B. Own canonical writer (JCS-like: sorted keys, integers and strings only). Trade-off: byte-stable forever; more code and tests.
   - C. Line-oriented text records (TSV). Trade-off: trivial to diff; weaker nesting.

12. **Toolchain upgrade policy.**
   - A. Pin go1.27.1 exactly, upgrade only with a golden regeneration pass and a changelog entry. Trade-off: stable outputs; delayed security fixes.
   - B. Track latest Go and accept golden churn when Unicode tables change (18.0.0 is next). Trade-off: current; recurring golden diffs on non-ASCII text.

13. **Languages and literature coverage (Q-16).** ELTeC includes Hungarian; Snowball has Hungarian; prose has no Hungarian model; no essay or news storyline corpus was found.
   - A. English only first. Trade-off: all resources exist; defers Hungarian.
   - B. English plus Hungarian (ELTeC-hun, Snowball, lexicon from scratch). Trade-off: matches the user's context; no ready sentiment lexicon or tagger.
   - C. Defer literature until the news network works. Trade-off: focus; the generic-core claim stays untested.
